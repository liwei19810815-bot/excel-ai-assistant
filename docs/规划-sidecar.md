# 规划：sidecar 伴生进程

> 状态：**方向已定（姿态 B：做，但用令牌严格把关）。第 1、2 步已完成，第 3 步待开工。**
> 第 1 步实测结论：**Office 可以创建子进程**，启动方式采用首选方案
> （Excel 打开工具箱时由 `.xlam` 拉起）。详见第四节。

## 一、它要解决什么

Office.js 有几件事**根本做不到**，不是 API 没做好，是沙箱边界：

| 做不到 | 用户侧的表现 |
|---|---|
| Power Query 刷新与编辑 | "帮我刷新一下数据源"做不了 |
| Power Pivot / 数据模型 / OLAP 透视表 | 数据模型类的活全做不了 |
| 调用 VBA / 宏 | 工作簿里现成的宏，AI 碰不到 |
| 文件系统 | 跨文件批处理、按文件夹合并 |

最后一类**工具箱本来就能做**（`merge.folder`、`file.list`、`file.batchRename`、
`file.exportSheets`、`file.insertImages` 五个命令）。

**真正只有 sidecar 能解决的是前三类**——工具箱里精确搜索 `PowerQuery`/
`WorkbookQuery`/`PivotCache`/`ListObjects`，零命中，它也没有这些能力。

## 二、安全约束是怎么来的

方向已定为"做"，但下面这些约束不是可选项，得先说清它们为什么存在。

### 威胁不是本地恶意软件，是用户打开的任意网页

本地恶意软件已经有用户的全部权限，多一个 sidecar 不改变什么。

**`127.0.0.1` 对本机所有浏览器进程都可达。** 用户在浏览器里打开任何一个页面，
那个页面的 JS 就能向 sidecar 发请求。

常见的误解是"有 CORS 挡着"。**CORS 挡的是读响应，不是发请求**：

```js
// 恶意网页里的代码，浏览器不会拦下这个请求
fetch('http://127.0.0.1:8899/run-macro', {
  method: 'POST',
  headers: { 'Content-Type': 'text/plain' },   // 简单请求，不触发预检
  body: '{"name":"某个宏"}'
})
```

请求**会真的发出去、sidecar 会真的执行**，浏览器只是不让那个页面读返回值。
在一个能执行 VBA 的端点上，"能触发但读不到结果"依然是灾难。

> **「内网使用所以风险小」只对一半。** sidecar 只绑回环，本来就不对网络暴露，
> 内网外网一个样。真正的入口是浏览器——只要那台机器能上网、
> 或能访问可能被 XSS 的内网站点，这条路就通。
> 只有**完全禁止浏览器上网**的机器，风险才真的接近零。

### 由此得到的七条约束

1. **只绑 `127.0.0.1`**，绝不 `0.0.0.0`
2. **256 位随机令牌**：安装时生成，写进 sidecar 配置，同时拼进该用户专属
   manifest 的 URL（`?sidecar=<token>`，复用现在注入 `?u=` 那条**已验证可行**的路子）。
   不带或不对一律 401。**远端网页猜不到这个串，这是整套防护的支点**
3. **`Origin` 校验**作为第二道，不是唯一一道
4. **白名单式接口**：只暴露"刷新查询""运行**指定名字**的宏"这类具体动作。
   **绝不做"传一段 VBA 进来执行"的通用口子**——那个口子把风险从"几个动作"
   放大到"任意代码执行"。要什么能力就加一个具体接口
5. 每个**改动性动作**都要任务窗格侧的人工确认（和 `run_script` 一致）
6. 用户**看得见、关得掉**
7. 能被 `feature.json` 治理开关一键禁掉（和关 AI 同一套机制）

**这七条都不牺牲易用性**——令牌用户看不见，只绑回环反而省掉了防火墙弹窗。
安全和简单在这件事上不冲突。

## 三、易用性设计：让用户根本不知道它存在

| 环节 | 做法 | 用户看到什么 |
|---|---|---|
| **安装** | 不单独装，并进现有一键安装包当一个组件（和 AI 组件一样） | 安装时多一个勾选项 |
| **启动** | **Excel 打开工具箱时，由 `.xlam` 用 `Shell()` 拉起** | 什么都没有 |
| **关闭** | 关 Excel 就没了 | 什么都没有 |
| **端口** | 固定端口 + 冲突顺延；任务窗格**带令牌**探一小段范围，认令牌的那个才是自己人 | 什么都没有 |
| **令牌** | 安装时注入 manifest URL + sidecar 配置 | 什么都没有 |
| **防火墙** | 只绑回环 → **Windows 防火墙不弹提示**（弹窗只针对非回环入站） | 什么都没有 |
| **升级** | 复用共享目录 + 版本化载荷（工具箱已验证过的机制），启动时自查 | 什么都没有 |

### 为什么选「Excel 打开时拉起」

这是整套方案里最省事的一点：

- 不用开机自启、不用常驻、不用托盘图标、不用教用户"先启动助手"
- **需要它的时候它正好在，不需要的时候它不存在**
- 安全上也更好：只在用户开着 Excel 的时候活着

**前提是 Office 能创建子进程**——见第四节，这是第 1 步要实测的事。

### 出问题时用户看到什么

**铁律：sidecar 不在 ≠ AI 坏了。**

- 任务窗格照常工作，只是 sidecar 类工具**从工具列表里消失**
  （模型根本看不到它们，不会承诺做不到的事）
- 右上角一个灰点 + 一行小字「本地助手未运行」
- **不弹窗、不报错、不拦着用户用别的功能**

和"网关挂了任务窗格照常可用"是同一条铁律。

## 四、第 1 步：Office 能不能创建子进程（实测）

整个启动方式取决于这一条。企业常部署一条 Defender ASR 规则
**「阻止所有 Office 应用程序创建子进程」**
（GUID `D4F940AB-401B-4EFC-AADC-AD5F3C50688A`），开了它这条路就断。

探测脚本：`Excel Macro/tools/check-office-child-process.ps1`（已交付）

它做两件事：
1. 读 ASR 规则的配置状态（说明性）
2. **真的驱动 Excel 跑一次 VBA `Shell()` 并验证进程确实起来了**（判定性）

> 只看注册表/策略不够——策略可能没下发但被别的机制挡住，
> 也可能配了 Audit 模式（记录但不拦）。**以实际能不能起进程为准。**

判定不止看 `Shell()` 有没有抛错：拿到 PID **不等于**进程起来了，
被拦时的典型表现之一就是"返回了 PID，但进程根本不存在"。
所以脚本会回头按 PID、再按命令行里的一次性 marker 去核实进程真的存在过。
核实不到就判 `INCONCLUSIVE`，**不会当成通过**。

### 怎么在用户机上跑

用户机上几乎都没开「信任对 VBA 工程对象模型的访问」，
所以脚本不能只靠"往工作簿里注入模块"这一条路。两条路都支持：

| 路径 | 用在哪 | 前提 |
|---|---|---|
| 探针加载宏 `AsrProbe.xlam` | **用户机** | 无（不需要 VBOM 信任） |
| 运行时注入模块 | 开发机 | 已开 VBOM 信任 |

操作：先在开发机上跑一次 `-MakeProbe` 生成 `AsrProbe.xlam`
（脚本会当场自检它真能被打开、真能被调用），
把它和脚本一起拷到用户机，在那边直接跑。
`AsrProbe.xlam` 是生成物，**不入库**。

两条路都不可用时脚本判 `INCONCLUSIVE` 并给出操作指引——
**不会因为"没测成"就报成通过。**

### 退出码

| 码 | 含义 |
|---|---|
| 0 | 能起子进程 |
| 1 | 被挡住 |
| 2 | 没测准（含"两条路都不可用"） |
| 3 | 探测本身出错，结论无效 |

四个分支都做过变异验证（把结果强行改坏，确认脚本真的会变红）。

### 结论与退路

| 实测结果 | 启动方式 |
|---|---|
| 能起子进程 | **Excel 打开时由 `.xlam` 拉起**（首选，最省事） |
| 被 ASR 挡住 | 退到**登录时启动**（Startup 文件夹快捷方式，不需要管理员）。代价是变成常驻进程，必须加托盘图标让用户看得见、关得掉 |

**必须在一台真实的用户机器上跑**。开发机通常没有部署企业 ASR 策略，
在开发机上通过不代表用户那边能用。

### 实测结果（第 1 步已完成）

| | |
|---|---|
| 机器 | DESKTOP-RD7D8L3 |
| 日期 | 2026-09-22 |
| 执行路径 | **探针加载宏**——和用户机走的是同一条路，不依赖 VBOM 信任 |
| 结果 | **通过**，退出码 0；VBA `Shell()` 返回 PID 15572，按 PID 核实到该进程确实存在 |
| ASR 规则状态 | 读不到——这台机器没装 Defender（`Get-MpPreference` 不存在） |

**结论：启动方式采用首选方案**——Excel 打开工具箱时由 `.xlam` 拉起，
关 Excel 就退出。不用开机自启、不用常驻、不用托盘图标。

> **这台机器没有部署企业 ASR 策略**，所以这个结果证明的是
> "在不拦的机器上这条路走得通"，**不等于**"在装了 ASR 的机器上也走得通"。
> 退路（登录时启动 + 托盘常驻）因此**不能从设计里删掉**——
> 铺开到一批装了企业策略的机器之前，在那边再跑一次这个脚本。
> 脚本已经交付，随时可跑，成本很低。

### 顺带踩到的坑（写下来免得再踩）

- **`CodeModule.AddFromString` 注入的工程，存成 `.xlam`/`.xlsm` 之后再也打不开**
  （`Workbooks.Open` 抛 `0x800A03EC`），而 `SaveAs` 那一步**不报错**。
  必须走 `VBComponents.Import(.bas)`——这也是 `build.ps1` 一直用 Import 的原因。
- `.bas` 仍然是那两条硬要求：**CRLF + 系统 ANSI**。
- `IsAddin` 必须在 `SaveAs` **之前**置上。
- `.ps1` **必须带 UTF-8 BOM**，否则 Windows PowerShell 按 ANSI 读，中文字符串直接把脚本解析坏。
- PowerShell 里**不能用 `$pid` 当变量名**——那是当前进程的自动变量，
  写进去等于在查脚本自己。

## 五、技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 语言 | **.NET** | 要驱动 Office COM，.NET 最顺；Node 走 COM 要额外原生模块 |
| 通信 | 本地 HTTP + 令牌 | 任务窗格是网页，只能走 HTTP/WS |
| 端口 | 固定 + 冲突顺延 | 随机端口任务窗格找不到 |
| 生命周期 | 跟随 Excel（首选）／托盘常驻（退路） | 见第三节 |

### 骨架已落地的部分（第 2 步）

代码在**工具箱仓库**：`Excel Macro/sidecar/ExcelToolboxSidecar.cs`，
构建 `build/build-sidecar.ps1`，回归 `tests/check-sidecar.ps1`（38 条断言）。

> 放在工具箱仓库是因为**发布链路整个在那边**：由 `.xlam` 拉起、
> 由 `Install-Toolbox.ps1` 写配置、由 `pack.ps1` 打进安装包。
> 代价是这份规划文档和它的实现分处两个仓库，改动要同时动两边。

几个定下来的选择：

| 项 | 选择 | 理由 |
|---|---|---|
| 编译器 | **系统自带的 `csc.exe`**，不用 dotnet SDK | 开发机不装 SDK、用户机不装运行时（.NET Framework 4.x 是 Windows 自带的）。代价：**只能写 C# 5 语法** |
| 监听 | **`TcpListener`，不用 `HttpListener`** | `HttpListener` 要 URL 保留（`netsh http add urlacl`），**非管理员拿不到**。开发者在开发机上是管理员，一跑就通，铺到用户机才发现起不来 |
| 令牌位置 | **只认请求头 `X-Toolbox-Token`** | 自定义头强制浏览器预检，远端网页发不出来。**查询串传令牌一律 400**——`?token=` 是简单请求、不触发预检，接受它等于自己把这道门拆了 |
| 令牌比较 | 定长比较 | 普通 `==` 在第一个不同字符处就返回，能被逐位试出来 |
| Origin | 整串相等，不用 `StartsWith` | 否则 `https://gw.corp.example.evil.com` 会被放进来 |
| 配置不合格 | **拒绝启动**（退出码 2） | 没有有效令牌还开端口，等于开了个谁都能用的本机后门 |

配置文件（第 3 步由安装器生成）：

```json
{
  "token": "<64 个十六进制字符 = 256 位>",
  "port": 8899,
  "allowedOrigins": ["https://<网关地址>"]
}
```

> `allowedOrigins` 解析踩过一个坑：`JavaScriptSerializer` 把 JSON 数组
> 反序列化成 `ArrayList` 而**不是** `object[]`，按 `object[]` 去转会得到 null，
> 结果是**白名单静默变空**——配置不报错、进程照常起、`/health` 也正常，
> 只是每个正常来源都被判 403。已修，并有断言守着。

七条变异（令牌改前缀比较、Origin 改 `StartsWith`、CORS 回 `*`、
绑全部网卡、接受查询串令牌、白名单解析退化、去掉父进程守护）
**逐条确认会让套件变红**。

### 与现有架构的接缝

- **能力探测**：任务窗格启动时探一次。不在就**安静降级**，把 sidecar 类工具
  从工具列表摘掉——和现在 `enableRunScript` 关掉时的做法完全一致
- **工具分级**：sidecar 的全部动作归到 `mutate:structure`，一律强制确认
